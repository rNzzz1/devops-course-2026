# Сравнение работы с Git: VS Code (IDE) vs Terminal (CLI)

## 3 вещи, которые удобны в VS Code для работы с Git

1. **Интерактивный просмотр различий (Side-by-Side Diff) и выборочный стейджинг (Stage Selected Ranges):**
   В графическом интерфейсе VS Code наглядно видны удаленные (красные) и добавленные (зеленые) строки с внутристрочной подсветкой конкретных символов. Возможность кликом мыши застейджить только определенный блок или пару строк (Hunk Staging) без необходимости вручную использовать интерактивный режим терминала `git add -p`.

2. **Встроенный редактор разрешения конфликтов слияния (Merge Conflicts Editor):**
   При возникновении конфликтов VS Code предоставляет интуитивный 3-way редактор с интерактивными кнопками: *Accept Current Change*, *Accept Incoming Change*, *Accept Both Changes* и *Compare Changes*. Это полностью исключает риск случайно оставить маркеры конфликта (`<<<<<<<`, `=======`, `>>>>>>>`) в кодовой базе.

3. **Интеграция с GitLens и визуальный Git Blame прямо в строке кода:**
   Расширение GitLens выводит аннотации авторства коммита прямо в конце текущей строки (кто изменил, когда, хэш коммита и описание), а также позволяет изучать дерево истории ветки, ассоциации с Pull Request и сравнивать любые произвольные ревизии в несколько кликов.

---

## 1 вещь, которую удобнее делать в терминале (CLI)

1. **Сложные манипуляции с историей (Interactive Rebase, Cherry-pick, Stash с ветвлением) и автоматизация скриптов:**
   Команды вроде `git rebase -i HEAD~N` (с гибким выбором действий *squash*, *fixup*, *reword*, *drop*), управление стешем `git stash push -m "desc" / git stash branch`, работа в headless-окружениях серверов по SSH без графической оболочки и встраивание команд Git в bash-скрипты автоматизации CI/CD выполняются в терминале значительно быстрее, прозрачнее и безопаснее.
