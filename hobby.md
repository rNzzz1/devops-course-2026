# Мой пет-проект

Идея: Telegram-бот для автоматизации дежурств (on-call) и агрегации алертов мониторинга в DevOps-команде. Бот распределяет расписание смен инженеров, интегрируется с Prometheus Alertmanager, принимает webhook-уведомления об инцидентах и маршрутизирует их дежурному специалисту с возможностью подтверждения (Ack) и эскалации.

Стек: Python 3.12 (aiogram 3.x, asyncio), FastAPI (webhook receiver), PostgreSQL, Redis, Docker & Docker Compose, GitHub Actions CI/CD.

Цель: Освоить разработку асинхронных микросервисных приложений, проектирование безопасных REST/Webhook интерфейсов, контейнеризацию в Docker и выстраивание полноценного CI/CD пайплайна с автоматическим линтингом, тестированием и сборкой образов.

## Архитектура и компоненты
1. **Webhook Receiver (FastAPI):** принимает входящие payload от Prometheus Alertmanager и внешних систем.
2. **Telegram Bot Service (aiogram):** логика взаимодействия с дежурными инженерами, клавиатуры подтверждения инцидентов.
3. **Database & Cache (PostgreSQL + Redis):** хранение истории алертов, журналов дежурств и кэширование состояния смен.
4. **CI/CD Pipeline (GitHub Actions):** автоматический линтинг (flake8, black), запуск pytest, сборка многоэтапного (multi-stage) Docker-образа и проверка уязвимостей (Trivy).

## Сроки и этапы реализации (Roadmap)
- **Этап 1:** Базовая архитектура бота и интеграция с Telegram Bot API.
- **Этап 2:** Эндпоинт приема вебхуков Alertmanager и логика фильтрации алертов.
- **Этап 3:** Хранилище расписаний и механизм эскалации инцидентов при отсутствии реакции в течение 5 минут.
- **Этап 4:** Настройка Docker Compose окружения и написание GitHub Actions Workflow.
